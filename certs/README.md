# Корневые сертификаты

## `russian_trusted_root_ca.pem`

Корневой сертификат УЦ Минцифры России, которым подписан сертификат
`*.tbank.ru`. Нужен для импорта операций из T-Invest API
(`apps/api/.../import/tbank/`).

```
subject/issuer  C=RU, O=The Ministry of Digital Development and Communications,
                CN=Russian Trusted Root CA
SHA-256         D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:
                35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31
действителен    01.03.2022 — 27.02.2032
источник        gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt (Госуслуги)
```

Почему он лежит в репозитории: это **публичный** корневой сертификат, не секрет —
как и любой корень из встроенного списка Node. Node доверяет вшитому списку корней
Mozilla и в системное хранилище macOS/Windows не заглядывает, поэтому tbank.ru
открывается в браузере, но запрос из бэкенда падает с
`SELF_SIGNED_CERT_IN_CHAIN`. Файл в репозитории делает запуск воспроизводимым:
команды запуска подставляют его через `NODE_EXTRA_CA_CERTS`.

Промежуточный сертификат (`Russian Trusted Sub CA`) скачивать не нужно — сервер
присылает его в цепочке сам.

**Область доверия.** `NODE_EXTRA_CA_CERTS` добавляет корень только процессу Node,
запущенному этой командой: системное хранилище сертификатов не трогается, проверка
TLS остаётся включённой, а рабочий каталог и платформа значения не имеют:
переменную подставляет `scripts/run-with-certs.mjs` — через него идут все команды
запуска. Это принципиально отличается от
`NODE_TLS_REJECT_UNAUTHORIZED=0`, который снимает проверку сертификатов вообще для
всех исходящих соединений — так делать не нужно.

**Обновление.** Срок действия истекает в феврале 2032. Когда понадобится заменить —
скачать заново с Госуслуг и сверить отпечаток:

```bash
openssl x509 -in certs/russian_trusted_root_ca.pem -noout -subject -issuer -fingerprint -sha256 -dates
```
