# 1. Собрать автономный сервер для Mac

Работай в проекте investment-portfolio. Прочитай `CLAUDE.md`, раздел запуска в `README.md` и статус в начале `docs/one-service-migration.md`. Реализуй задачу в коде. Эта сборка станет содержимым будущего macOS-приложения. Результат этой сессии должен запускаться сам по себе.

## Что сделать

- Добавь воспроизводимую команду сборки для Apple Silicon. Она должна собрать Angular и NestJS и подготовить каталог со встроенным Node, сервером, фронтендом, миграциями с журналом, сертификатом T‑Invest и фактическими runtime-зависимостями. Проверь externals в `apps/api/webpack.config.js` и загрузку нативного `better-sqlite3` именно вложенным Node. Зафиксируй совместимую версию Node, архитектуру и источник поставки. При скачивании проверяй контрольную сумму.
- Сделай точку запуска, которую потом сможет вызвать Swift. Явно раздели каталог ресурсов и пользовательские данные. Учти, что `load-env.ts` должен отработать до открытия SQLite, а `NODE_EXTRA_CA_CERTS` — до запуска Node. Сейчас `scripts/run-with-certs.mjs` может записывать объединённый сертификат в `tmp` рядом с кодом. Для установленной версии направь запись в пользовательский каталог. Оставь рабочими команды запуска из репозитория.
- Сервер установленной версии слушает loopback. Добавь минимальную проверку готовности `GET /api/health`. Готовность означает, что миграции прошли, а установленная версия может отдать интерфейс. Обеспечь штатную остановку по SIGTERM с освобождением порта и закрытием SQLite. Если используется обёртка, проверь завершение её дочернего процесса.

## Как принять

Перенеси сборку во временную папку с пробелами в пути, запускай из другой рабочей директории, с временной базой, без доступа к зависимостям репозитория и без системного Node в PATH. Проверь дашборд, прямой переход на страницу операций, health, реальный запрос к SQLite, остановку и повторный старт. Проверь, что в сборку не попали рабочая база, отчёты и личный `.env`.

В ответе для следующей сессии укажи ветку и коммит либо состояние незакоммиченного diff, команду сборки, путь к результату, команду запуска и остановки, параметры путей и порта. Приведи фактически выполненные проверки и то, что осталось проверить на чистом Mac. Для всех проверок используй временные данные.
