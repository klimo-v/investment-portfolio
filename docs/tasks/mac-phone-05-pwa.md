# 5. Установка портфеля на домашний экран телефона

Работай в проекте investment-portfolio с результатами задач 1–4. Прочитай `CLAUDE.md`, `apps/web/project.json`, `apps/web/src/app/app.config.ts`, `apps/web/src/index.html` и `apps/api/src/serve-spa.ts`. Сделай PWA из существующего Angular-приложения. Телефон использует ту же базу на Mac через HTTPS-адрес из задачи 4.

## Что сделать

- Для production-сборки добавь манифест, название, режим standalone, иконки для iOS и Android и совместимый с текущим Angular service worker. Проверь реальные URL файлов в сборке Nx. В режиме разработки сохрани обычное поведение без кэширования сборки.
- Исправь SPA fallback. Прямое открытие маршрута вроде `/operations` отдаёт приложение. Для отсутствующих JS, иконок и файлов PWA сервер возвращает настоящий 404, неизвестный `/api/*` сохраняет JSON 404. Учти и правила навигации самого service worker.
- Кэшируй только оболочку и ресурсы интерфейса. Сделай иконки и офлайн-экран независимыми от Google Fonts. Финансовые ответы `/api` исключи из кэша service worker и HTTP-кэша. После первого успешного онлайн-запуска с активным worker при недоступности API покажи «Нет связи с Mac» и «Повторить». Интернет может работать, пока спит Mac или отключён Tailscale. Сохраняй различие между потерей связи и обычной ошибкой проверки данных. Не ставь операции в офлайн-очередь и не повторяй автоматически запись с неизвестным исходом.
- Проверь дашборд, журнал и форму операции на узком экране. После записи с телефона обновляй данные открытой вкладки Mac при возврате в неё или явном обновлении. Используй существующий механизм повторного запроса. Для новой версии оболочки предусмотрен безопасный переход с перезагрузкой в подходящий момент без потери незавершённого ввода.
- Добавь короткую инструкцию для iPhone и Android. Пользователь открывает HTTPS-ссылку из QR-кода, затем добавляет портфель на домашний экран. Пересобери итоговый .dmg с результатами всех предыдущих задач и PWA.

## Как принять

Проверь production-сборку через настоящий сервер: рабочий deep link, 404 для пропавшего файла, типы манифеста и worker, активацию worker, повторный запуск без связи, восстановление соединения и переход с предыдущей сборки. На тестовом портфеле пройди сценарий «добавить операцию на телефоне → увидеть её на Mac», проверь отсутствие финансовых ответов в кэше и отсутствие дубля после обрыва связи. При наличии устройств проверь установку через Safari на iPhone и Chrome на Android. Отдельно отметь проверки, сделанные только в браузере или эмуляторе.

Верни ветку и коммит либо состояние diff, команды проверок, фактические результаты и путь к итоговому образу. Укажи статус его подписи и оставшиеся проверки на реальных устройствах. Тестовые данные, токены и ключи подписи должны оставаться вне образа.
