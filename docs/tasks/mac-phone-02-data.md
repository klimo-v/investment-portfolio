# 2Б. Восстановление на новом Mac и резервная копия перед обновлением

Работай в проекте investment-portfolio с результатами задач 1 и 2А (`docs/tasks/mac-phone-02a-backup-ui.md`). Используй формат резервной копии и общий механизм проверки и восстановления из 2А. Изучи точку запуска сервера, `CLAUDE.md`, `apps/api/src/load-env.ts` и порядок открытия базы и применения миграций. Реализуй вызов этого механизма до открытия рабочей базы. Его подключит мастер первого запуска на Mac.

## Что сделать

- Поддержи «Начать с пустого» и «Восстановить из резервной копии». Основной сценарий переноса на другой Mac — выбрать один скачанный файл из 2А, включая полностью загруженный файл из облачной папки. Восстанови данные в локальный профиль нового Mac. Сохрани также возможность переноса прямо из старого проекта с учётом его фактического `DB_PATH`, включая относительные пути. При неверном пути покажи ошибку и дай выбрать файл повторно. В этом случае пустая база создаваться не должна.
- Храни профиль в `~/Library/Application Support/Investment Portfolio/`. Путь для теста должен переопределяться. При переносе создай временную согласованную копию через SQLite Backup API с учётом WAL. Проверь, что это поддерживаемая база портфеля, прогони существующие миграции на копии, проверь целостность и только затем сделай её рабочей. Учти повторный запуск после прерывания. Уже существующий рабочий профиль нельзя молча перезаписывать.
- Дай возможность отдельно перенести настройку T-Invest. Защити токен средствами пользовательского профиля, исключи его из журналов и отчёта. Старые сетевые настройки и пути могут указывать на работающий dev-сервер, поэтому перенос разрешённых настроек сделай явным.
- Перед обновлением, которое меняет схему установленной базы, обеспечь согласованную резервную копию и понятный путь восстановления совместимой пары «приложение + база». Учти порядок старта из задачи 1 и несколько стадий существующих миграций.

## Как принять

Проверь на временных базах пустой старт, перенос заполненного портфеля с зафиксированными изменениями в WAL, перенос со старой схемы, неверный файл, ошибку миграции, прерывание и повтор. Отдельно возьми файл, созданный веб-интерфейсом 2А, перенеси его в чистый профиль без доступа к исходному репозиторию и восстанови. После восстановления проверь, что приложение работает и при недоступном исходном файле. На контрольном наборе сравни число операций и итог портфеля при одинаковых котировках. Покажи, что исходная база сохранилась и из предмиграционной копии действительно можно восстановиться. Рабочую базу пользователя для экспериментов не используй.

Верни ветку и коммит либо состояние diff, список изменённых файлов, способ вызвать каждое действие из Swift, выполненные команды и результаты. Отдельно укажи, что понадобится проверить при подключении экрана первого запуска.
