# 3. Приложение в строке меню macOS и установочный образ

Работай в текущем рабочем каталоге investment-portfolio на ветке `feat/system-performance`. Сохрани незакоммиченные изменения задач 1, 2А и 2Б. Прочитай `CLAUDE.md` и `docs/mac-runtime.md`. Реализуй пользовательский сценарий целиком для Apple Silicon. Перед выбором минимальной версии macOS сверь требования Swift API, встроенного Node и нативного SQLite-модуля.

## Что должно получиться

- Пользователь открывает DMG, переносит Investment Portfolio.app в «Программы» и запускает. При первом запуске доступны «Восстановить из резервной копии» и «Начать с пустого», а для владельца старого проекта — перенос из его каталога. Подключи механизм 2Б. Прими тот же файл, который скачивается в разделе «Данные» из 2А. Покажи выбранный путь и результат. Отмена выбора позволяет вернуться к мастеру до запуска сервера.
- Сделай небольшое приложение на Swift с иконкой в строке меню. Покажи состояния «Остановлен», «Запускается», «Работает» и ошибку с понятной причиной. Добавь «Запустить», «Остановить», «Открыть портфель», «Запускать при входе» и «Выйти». Автозапуск реализуй через `SMAppService.mainApp` на поддерживаемых системах, отобрази состояние системного разрешения. Кратко опиши поведение при входе и после ручной остановки.
- Приложение владеет процессом своего сервера. Повторное нажатие запускает только один экземпляр. Перед открытием браузера проверь готовность именно своего процесса. При занятом порте покажи ошибку, сохрани чужой процесс. Закрытие браузера оставляет сервер работающим, явные «Остановить» и «Выйти» дожидаются завершения. Проверь также повторное открытие приложения после сбоя. Логи доступны в пользовательском каталоге.

## Как выпускать следующие версии

- Сделай одну документированную команду, которая принимает номер версии, пересобирает сервер, веб-интерфейс и миграции из текущих исходников, упаковывает автономный runtime в `Investment Portfolio.app` и создаёт `Investment-Portfolio-<версия>-arm64.dmg`. Результат должен быть корректным и при наличии старых файлов в `dist`. Имя приложения, его bundle ID и расположение пользовательского профиля должны оставаться стабильными между выпусками.
- Покажи версию и номер сборки в меню приложения или в окне «О программе». Версия в имени DMG и в приложении должна совпадать. Добавь краткую инструкцию для повторного выпуска после исправления или новой функции, включая проверку обновления и подготовку списка изменений.
- Для публичного выпуска подготовь подписание через Developer ID с hardened runtime, включая вложенные исполняемые файлы и нативный модуль, нотарификацию и stapling. Сохрани возможность собрать и проверить локальный образ без учётных данных Apple.

## Как пользователь обновляется

Пользователь выбирает «Выйти», открывает новый DMG, заменяет приложение в «Программах» и запускает его. Новая версия открывает существующий профиль без мастера первого запуска и ручного экспорта или импорта. Используй контракт обновления и отката из `docs/mac-runtime.md`. Учитывай, что Finder заменяет старое приложение до запуска нового. Для миграции используй сохранённый runtime предыдущей версии и согласованную копию базы. При ошибке покажи понятную причину и способ вернуться к рабочему портфелю.

## Как принять

На временном профиле проверь из Finder пустой старт, восстановление из скачанной копии, отмену выбора и перенос из старого проекта. Проверь запуск, остановку, повторный запуск, занятый порт, закрытие вкладки и выход. Где доступны подходящий Mac и подпись, проверь скачанный DMG через Gatekeeper. Сетевой доступ с телефона будет отдельной задачей.

Добавь повторяемую проверку обновления, которая принимает два готовых DMG и работает в отдельном каталоге установки с временным профилем:

1. Установи приложение из предыдущего DMG. Создай тестовый портфель и через приложение зафиксируй контрольные данные: выбранный счёт, конкретную операцию с датой и суммой, количество операций и итог в фиксированной тестовой выборке.
2. Заверши приложение штатно. Замени его в том же каталоге приложением из нового DMG и запусти. Проверь, что работает новая сборка, мастер первого запуска не появился, а счёт, операция, количество и итог совпадают. Добавь ещё одну операцию, перезапусти и проверь сохранность записи.
3. Проверь обычное обновление без изменений схемы и обновление с миграцией на тестовой базе. Для сценария сбоя проверь, что неудачная миграция сохраняет прежний портфель и его можно снова открыть. Для проверки первого выпуска, пока предыдущего публичного DMG ещё нет, используй две явно обозначенные локальные тестовые сборки. Для последующих выпусков бери фактический DMG предыдущего релиза.
4. Отдельно восстанови обезличенную копию с историческим вариантом миграции `0011_strategy_configs` через сервер внутри готового приложения из нового DMG. Это регрессия случая, когда исправление импорта было в исходниках, а в сборку попал старый сервер.

Оставь diff без коммита. Верни пути к .app и .dmg, команды сборки и проверки обновления, минимальную версию macOS и фактический статус подписи и нотарификации. Для проверки обновления укажи обе версии, происхождение образов и контрольные значения до и после. Перечисли действия, проверенные через интерфейс, и оставшиеся ручные проверки.
