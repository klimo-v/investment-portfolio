# Срез «ЮВ1»: учёт ТС ЮВ1·2вх по мосту QUIK

Отдельный срез для срочного рынка. Таблицы `operations`, движок `engine.ts` и существующий импорт отчётов
не затронуты: фьючерсы, шорт, вариационная маржа и ГО в модель спота не вписываются.

## Откуда данные

| Источник | Что даёт | Доверие |
|---|---|---|
| `qsnap_raw.csv` + `qsnap_index.csv` (мост) | сделки с миллисекундами, цены, комиссии биржи и клиринга, позиции, рубли Т0/Т1, ВМ, `calc_trades` | только **целые** снимки |
| `yv1_trades.csv`, `yv1_trades_before_*.csv`, `yv1_fills.csv` (автомат) | **принадлежность сделки ТС**, причина (h1/h2/exit), `ref_price` | правило принадлежности |
| `yv1_daily.csv`, `yv1_signals.csv`, `yv1_log_*.txt` (автомат) | итоги дней, сигналы по половинам, размер на старте, остановки (halt) | справочно |

Каталог моста только читается (`QUIK_BRIDGE_DIR`, по умолчанию `~/quik_bridge/from_quik`). Тест
`файлы моста при импорте не меняются` сравнивает хэш каталога до и после.

### Когда снимку можно верить

Снимок целый, только если одновременно: в индексе есть его строка со `status=ok`, `raw_lines` равно числу строк
этого `snap_id` в raw, `float_ids = 0`. Остальные записываются в журнал снимков (видны на странице), но их
сырьё не импортируется и в расчёт они не идут. `snap_id` без строки индекса — «незавершённый». Неизвестная
`script_version` — ошибка с понятным текстом (поддерживаются 2 и 3).

### Правило времени

Все моменты из таблиц QUIK (`datetime.*`) — биржевое время, то есть МСК, и **не сдвигаются**. `local_time`
снимка — часы машины со скриптом (МСК). `server_time` (без даты) ночью «отстаёт» ~30 мин и нигде не
используется как момент события; разница `local − server` сохраняется в `qsnap_snapshots.clock_skew_sec` как
диагностика. Подтверждение: выход 06.11 в таблице — 10:20:00.939, в логе автомата — 10:20:00.

### Принадлежность сделки

Сделка относится к ТС, если её `trade_num` есть в журнале автомата (счёт + `CR*` + `trade_num`). Остальные сделки по
`CR*` — **«не распределено»** (в расхождениях: `manual-trade`, с пометкой «время похоже на систему», если это
~10:20/13:00/15:00). Сделки не по `CR*` (фонд SBMM) в ТС не входят, участвуют в тесте полноты.

## Цикл и результат

Единица — цикл: входы по половинам (h1 13:00, h2 15:00) → выход следующего торгового дня (10:20), включая выходные и
смену контракта. Сопоставление — FIFO по контракту; цикл = день открытия лота.

* **Результат по цене** — точен по ценам сделок, `1 контракт = 1000 ₽ × цена`.
* **Издержки:** брокер = `сумма × 0.015 %`, округление **вверх до копейки** по сделке (см. «Калибровка»);
  биржа и клиринг — поля QUIK (совпали с отчётом Сбера); `broker_comission` QUIK **не используется** (завышена ≈ 2.64×).
* **Проценты по долгу** от минусовой ВМ: модель `0.06 %/сут` на минус рублей Т0 (утренние остатки). Ставка —
  со слов пользователя, по документу не проверена; факта в мосте нет.
* **net = результат по цене − издержки − проценты по долгу.** Налог не учтён (как и в бэктесте).
* **Вариационная маржа** показывается по дням счёта отдельно («начислена» / «проведена»): `varmargin` в снимке до
  клиринга — индикатив (см. 572 против 496 за 29.10). В net она не входит — результат по цене от неё не зависит.
  На циклы ВМ не раскладывается: в день смены цикла на один клиринг приходятся два цикла.

## Знаменатель

Задаётся явно (`PUT /api/yv1/settings`, поле на странице). Если не задан — берётся `CAPITAL` из последней
строки «старт:» лога автомата (подписано «из лога автомата»). Доходность цикла показывается к **начальному** капиталу и
к **текущему** (начальный + net закрытых до входа циклов). Размер позиции по датам виден в логах (`sizing`): 2
контракта на половину до 30.10, дальше от капитала с плечом 1.25.

## Проверки точности

Допуски сверки qsnap ↔ автомат заданы в коде (`RECONCILE_TOLERANCE`) **до первого прогона**: цена и количество —
точно, время — 2 с, комиссии — 0.01 ₽.

| Проверка | Где в списке расхождений |
|---|---|
| сделка есть в одном источнике и нет в другом (только для дат с целым снимком) | `only-in-automat`, `manual-trade` |
| время, цена, количество, сторона, контракт, комиссии | `mismatch-*` |
| одна сделка по-разному в разных снимках | `snapshot-conflict` |
| пропущенная половина, частичное исполнение, «исполнено» в сигналах ≠ по сделкам | `missed-half`, `partial-fill`, `signal-fill-mismatch` |
| halt автомата; выход не в 10:20; выход без позиции; вход закрыл вчерашнюю позицию | `halt`, `exit-not-1020`, `exit-without-position`, `entry-closes-position` |
| позиция снимка: `startnet + сделки = totalnet` | `position-mismatch` |
| `calc_trades` против модели и полей сделки | `calc-trades-diff` |
| **тест полноты** — изменение рублей Т1 за день = комиссии QUIK по ТС + по «не распределено» + сделки фонда + проведённая ВМ | `money-identity` |
| покрытие: у каждого торгового дня целый снимок **после 19:10 МСК** | `coverage-hole` |

Вердикты: пока закрытых циклов < 30 — только «предварительно». Коридор (`docs/yv1-corridor.json`) задаётся заранее и
не подгоняется; пороги паузы из стратегического репозитория не менялись и не используются здесь.

## Использование

```bash
pnpm yv1:refresh                    # мост + журнал автомата → БД, сводка; миграции применяются как при старте API
pnpm yv1:refresh --curve out.csv    # плюс кривая date,ret,equity (существующий файл не перезаписывается)
```

В приложении: пункт стратегии в боковом меню (`/strategies/:systemId`) → «Обновить из моста». Эндпоинты по `systemId`:
`GET /api/strategies` (список), `GET /api/strategies/:systemId/overview`, `POST .../refresh`, `GET|PUT .../settings`,
`PUT .../portfolio` (`{"portfolioId": "..."}`), `GET .../curve.csv`.

Портфель стратегии выбирается списком в шапке страницы стратегии (или `pnpm yv1:refresh --portfolio Trader`, или
`PUT .../portfolio`) — один раз; у ЮВ1, перенесённой миграцией, портфель сначала пустой. Пересчитывать ничего не нужно:
лента результата читает портфель из конфига.

Переменные окружения: `QUIK_BRIDGE_DIR`; `YV1_BACKTEST_CSV` (по умолчанию
`../strategy-backtester-vectorbt/data-reports/yv1_2vh_rub_report_2026-11-05/daily_yv1_2vh.csv`, только чтение);
`YV1_CORRIDOR_FILE`.

Как снимать мост, чтобы не было дыр: запускать `quik_snapshot.lua` (1) после 15:06 — сделки дня до смены торговой даты,
(2) после 19:10 — ВМ по расчётным ценам, (3) утром после 09:45 — комиссии за вчера и итоговые рубли. Таблица `trades` в QUIK хранит
**только текущую торговую дату** (по снимкам 06.11 в ней нет сделок 04–05.11), поэтому пропущенный день из моста не восстановить;
закрывается журналом автомата или отчётом Сбера.

## Калибровка

* Эталон Сбера 26–30.10 (3 сделки): брокер 14.78, биржа 4.52. Округление вверх по сделке даёт 3.69 + 3.69 + 7.40 = **14.78**, обычное —
  14.77. Выбрано «вверх» (`DEFAULT_FEE_ROUNDING`), это гипотеза по трём точкам; переключается настройкой `feeRounding`.
* `calc_trades` скрипта округляет обычным способом, поэтому расходится с моделью на копейку (допустимо, фиксируется в `maxBrokerDiff`).
* Оценка QUIK / модель по брокеру ≈ 2.64 — как в отчёте 02.11.
* В рублях Т1 ночного снимка стоят комиссии по **оценке** QUIK и нет ВМ: Δ Т1 06.11 = −1346.40 (SBMM) − 628.98 (оценка комиссий) = −1975.38,
  невязка 0.00. Поэтому итоговые деньги брать из утреннего снимка, а не из ночного.

## Стратегии и портфель

* **Конфиг стратегии** — строка `strategy_configs`: `systemId` (торговая система), `portfolioId` (счёт), `adapter`
  (сейчас `quik-bridge`), `params` (JSON; `journalPrefix` — префикс файлов журнала автомата, по умолчанию `yv1`).
* **Два уровня данных.** Снимки моста — данные счёта (`qsnap_*`, `portfolio_id`); журнал автомата, циклы, настройки —
  данные стратегии (`system_id`). Вторая стратегия на том же счёте добавляет только свой журнал; сделки, которых нет ни в
  одном журнале, — «не распределено».
* **Результат в портфеле.** `refresh` пересобирает ленту `strategy_daily_results` (реализованный net по дате закрытия
  цикла). `OperationsService.summary()` добавляет её в «Реализ.», P&L системы/портфеля/итогов и в свободные деньги.
  Не входит: XIRR (считается по операциям), частично закрытые циклы.
* **Новая стратегия:** пункт «Новая стратегия» в боковом меню (или `POST /api/strategies` с телом
  `{ name | systemId, portfolioId, params: { journalPrefix } }`). Создаёт систему (если дано `name`) и конфиг одной
  транзакцией. Префикс журнала обязателен и уникален: он определяет файлы автомата в каталоге моста
  (`<префикс>_trades.csv` и т.д.). Другой формат источника = новая реализация `StrategyAdapter` и ветка в
  `createStrategyAdapter` (`apps/api/.../strategies/strategy-registry.ts`).
* **Удаление стратегии:** кнопка на странице стратегии или `DELETE /api/strategies/:systemId?force=true`. Удаляются конфиг,
  журнал автомата (сделки, дни, сигналы, логи), настройки и лента результата в портфеле; результат стратегии из
  портфеля пропадает. Остаются торговая система (на неё могут ссылаться операции; удаляется отдельно в «Системах»),
  снимки моста (данные счёта) и файлы источника. Без `force` при наличии данных сервер отвечает 409 с перечнем потерь.
* **Несколько стратегий на одном счёте.** Сделки счёта из журнала другой стратегии для текущей не «не распределено»:
  хранилище передаёт в обзор номера сделок чужих журналов (`otherStrategyTradeNums`). Такие сделки не попадают в циклы
  и в расхождения `manual-trade`, считаются отдельным счётчиком `counts.otherStrategy`, а в тесте полноты — своей
  группой `other-strategy` (невязка не меняется). У одной стратегии вывод прежний. Остаётся «не распределено» только то,
  чего нет ни в одном журнале.

## Что не сделано / ограничения

* **Журнал автомата в БД только накапливается:** импорт делает upsert по `trade_num` и ничего не удаляет. Сделка, пропавшая из
  `yv1_trades.csv` (или с исправленным `trade_num`), остаётся в БД — это сознательно (история), но «сделок в файле» и «сделок в обзоре»
  тогда расходятся. Чистка — вручную.
* **Проценты по долгу** считаются по утреннему Т0 дня и, вероятно, недосчитывают первую ночь долга; проверить можно только на реальном
  минусовом остатке (пока рубли не уходили в минус).
* **Ротация `qsnap_raw.csv`** на стороне моста сделает уже импортированные снимки «конфликтами» (файл изменился) — мост пока только дописывает.
* При нескольких клиентских кодах без строки лимита Т0 у второго тест полноты может смешать счета; в имеющихся данных такого нет.

* **Контрфактический прогон** по правилам автомата на живых датах и новый датированный отчёт в `data-reports/` стратегического
  репозитория не делались (репозиторий только для чтения). Бэктест на странице — справка: его кривая кончается 19.10, общих дат с
  живой торговлей нет.
* **Проскальзывание выхода** против open 10:20 — нужны свечи; сейчас считается только если передать `exitRefPrices`. Вход — против `ref_price` автомата.
* **Сверка с отчётом Сбера** (комиссия, ВМ, рубли) — парсера срочного раздела нет: в образце отчёта его нет; нужен образец.
* Направление сделки по флагам заявки (`0x4` = продажа) проверено только на покупках; расхождение с автоматом подсвечивается (`mismatch-side`).
* Налог и факт процентов по долгу в мосте не наблюдаются.
